# TraceChat 产品迭代说明：支线库与引用清理

本次迭代在 `product-iteration-docs` 分支完成，目标是让支线不只依附在单条主线消息旁，也能成为会话级的可管理资产。

## 新增特性

### 1. 会话级支线库

主界面右侧新增“支线库”面板，展示当前会话下的全部支线。用户可以不回到原始主线消息，直接查找并打开历史支线。

能力包括：

1. 按更新时间倒序查看当前会话的支线。
2. 点击支线卡片后打开对应支线详情面板。
3. 卡片展示支线标题、状态、选中文本、摘要和更新时间。
4. 支持查看活跃、保存、回填、折叠、归档等状态。

### 2. 支线状态筛选

支线库顶部新增状态筛选器：

1. 全部
2. 活跃
3. 已保存
4. 已回填
5. 已折叠
6. 归档

这让用户可以把“临时查询”“已沉淀结论”“已归档材料”分开管理。

### 3. 支线关键词搜索

支线库新增本地搜索框，支持按以下内容搜索：

1. 支线标题
2. 支线摘要
3. 来源选中文本

搜索用于快速找回之前的旁路推导、背景资料和已回填结论。

### 4. 主线引用发送后自动清理

此前用户把某个支线摘要“引用到输入框”后，发送一次主线消息，引用状态仍会保留，下一次发送可能误带同一个支线引用。

本次迭代调整为：主线回复流式完成后，自动清空本次引用的支线列表。这样引用更接近“一次性上下文注入”，降低误污染主线的风险。

### 5. 切换会话时清理支线工作区

切换会话时，现在会同步清理：

1. 已打开的支线标签
2. 当前激活支线
3. 支线消息缓存
4. 正在引用的支线
5. 当前文本选择

这避免了跨会话残留支线面板或错误引用的问题。

### 6. 启动后自动进入最近会话

应用加载会话列表后，如果当前没有激活会话，会自动打开最近更新的会话并加载主线消息。用户不再需要每次刷新页面后手动重新选择最近的工作上下文。

### 7. 主线模型上下文修正为最近消息

后端构造主线模型上下文时，现在按消息序号倒序取最近 20 条，再恢复为正序传入模型。此前逻辑实际更容易取到较早的 20 条消息，长会话中会削弱最近上下文的相关性。

## 产品价值

这次改动把支线从“主消息上的局部标记”提升为“会话内可检索、可筛选、可复用的知识片段”。它更贴近 TraceChat 的核心目标：主线保持连续，支线负责承载临时解释、验证和沉淀，并在需要时被用户显式带回主线。
